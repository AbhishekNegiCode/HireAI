# Suggested university demonstration

1. Open the Mermaid ER diagram and show user/profile, skill and application relations.
2. Sign in as `maya@candidate.example` using the development password in README.
3. Show live dashboard counts; change a profile skill and refresh AI matches.
4. Compare matching skills, optional gaps and all four component scores on AI matches.
5. Upload a fictional PDF/DOCX resume; show private download and the missing-key state
   or real structured extraction if you configured Groq. Correct information and import skills.
6. Open a job, view the skill roadmap, save it and apply. Attempt a duplicate application.
7. Sign in as the owning seeded recruiter, open applicants, filter by skill/experience,
   inspect the submitted resume and set status to Shortlisted.
8. Return to the candidate application history and show timestamps.
9. Show the same application/history rows in SQL; demonstrate a rolled-back status update.
10. Explain the SQL required-skill function and pgvector cosine query, then compare
    EXPLAIN ANALYZE plans and discuss why small tables may use sequential scans.
11. Provision an admin through the CLI and demonstrate reports, account suspension and
    job closure. Do not use a real person's data for the demonstration.
